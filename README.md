# r9700-rdna4-research — dual R9700 LLM serving benchmark results

**Open benchmark results for serving `Qwen3.8-27B` on a dual AMD Radeon AI PRO R9700 (gfx1201 /
RDNA 3.5) box.** This repo shares the measured **data, reports, comparison graphs, and the exact
vLLM parameters** for each setup tested — so anyone with the same hardware can reproduce or compare
against them. No benchmark number here is guessed.

## Hardware

2× AMD Radeon AI PRO R9700 — Navi 48, **gfx1201** (RDNA 3.5), 32 GiB VRAM each, 300 W, **no xGMI**
(TP=2 all-reduce over host SHM / PCIe 5.0 x16) · Ryzen 9 9950X · 125 GiB DDR5 · CachyOS · ROCm 7.2.4.

### Headline results (2× R9700, TP=2)

**Campaign 1 — AITER vs TRITON (FP8 vs MXFP4), 64K/128K/256K windows:**

![128K leaderboard](results/vllm-aiter-triton/report/graphs/g7_leaderboard_128k.png)

- **TRITON (`TRITON_ATTN`) + FP8** is best all-round: +25–40% long-context decode vs AITER;
  FP8 +11–15% vs MXFP4 on decode; **AITER capped at 128K** (only TRITON serves 262K).
  Concurrency peak **673 t/s @32 users**.

**Campaign 2 — radiance R4D + DFlash2:**

- **Decode is content-dependent**: 185–193 t/s on structured/deterministic output, ~64 t/s on open-ended
  prose; and it **holds ~150–165 t/s even at 128K/160K resident** (robust long-context decode).
- Prefill falls **2.9k → 2.1k t/s** as context grows 8K → 160K (the server's max, substituting for 256K).

## What's in here

```
results/
├── vllm-aiter-triton/         report/ · data/ · PARAMS.md
└── vllm-radiance-dflash/      report/ · data/ · PARAMS.md
```

Each campaign folder is self-contained: **`report/REPORT.md`** is the write-up, **`report/graphs/` ·
`report/figs/`** the comparison charts, **`data/`** the raw per-run JSON, and **`PARAMS.md`** the exact
vLLM flags used. The runner scripts that generate these live in the local-only `dev/` folder (not
shared) so the public repo stays focused on results.

## Methodology (apples-to-apples)

Same flags, same inputs; only hard dependencies change (attention backend, image, model, NCCL env).
Scenarios: single-user prefill+decode (windows), 1→32-user concurrency, and a harness-agent coding
task. Metrics: TTFT, prefill PP, decode TG, end-to-end t/s — always from the server `usage` (never
SSE chunks).
